## 5. API compared with the suggested endpoints (§22)

Implemented as suggested: auth, dashboard, ticket list/detail/timeline/process, processing ingest and
status, duplicates (detect, list, link, unlink), knowledge documents/chunks/search, approvals
(list, approve, reject, escalate), evaluations, analytics cost and model usage, settings, audit logs.

| Suggested | Status |
|---|---|
| `POST /tickets`, `PATCH /tickets/{id}`, `POST /tickets/{id}/reprocess` | Not built: tickets come from ingestion; `POST /tickets/{ref}/process` re-runs the pipeline |
| `GET /processing/{id}/results` | Covered by `GET /processing/{ref}/status` and `GET /tickets/{ref}/routing` |
| `POST /classification/predict`, `GET /classification/{id}` | Not built as separate endpoints: classification runs inside `/tickets/{ref}/process`; results appear in `/tickets/{ref}/routing` |
| `POST /knowledge/documents` (upload), `POST /knowledge/documents/{id}/index` | Not built: `POST /knowledge/index` rebuilds from the source mirror |
| `POST /rag/query`, `GET /rag/retrieval/{id}` | Not built: needs a drafting model; `POST /knowledge/search` covers retrieval and logs a retrieval id |
| `GET /analytics/cost-per-ticket` | Included in `GET /analytics/cost` |

Added beyond the suggestion: the approval draft and decision endpoints, `/memory`, the DPO PII reveal,
`/statutory/rates`, `/sla/reconciliation`, dashboard breakdowns and routing performance, and `/ready`.
